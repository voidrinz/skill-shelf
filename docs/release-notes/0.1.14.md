# What's New

- The Workbench now opens a dedicated Agent access workspace instead of expanding Agent rows. Choose an Agent from a searchable sidebar, then switch between shared Skill access, local files, and Agent information.
- Connect selected global shared Skills using symbolic links or independent copies. Inspect each Skill's source, Agent path, ownership, and status in a separate details panel, and review every filesystem operation before confirming.
- Managed copies now distinguish matching files, source updates, and local modifications using file-content and executable-bit fingerprints. Unchanged copies can be updated manually; locally modified copies are protected from replacement and removal.
- Repair managed links or disconnect managed relationships without deleting the shared source. Existing external links and folders remain visible but are never adopted, overwritten, or removed by this workspace.
- Access previews expire and recheck paths, contents, and ownership when applied. Failed filesystem changes attempt rollback; retained recovery files and incomplete post-operation checks are reported explicitly, including recovery folders rediscovered after restarting the app.
- Returning from a preview preserves the shared-access search, filter, connection mode, selection, and inspected Skill. Returning to the Workbench preserves overview filters and restores focus. Agent and view switching are disabled while filesystem changes are applied.
- Corrected shared Skill coverage for hidden universal readers. Overview counts describe matching Skill names rather than verified copies or execution, and Skills outside the shared directory appear as an additional-local-Skills note.

## Access Scope

Agent access manages global shared Skills from `~/.agents/skills` in Agent-specific directories. Agents that read the shared directory directly need no additional links or copies. Project deployments and independent Pack copies keep their existing workflows.

Symbolic links share the original files, so edits through an Agent path also affect the source and other linked Agents. Independent copies do not synchronize automatically; source updates require a new preview. Filesystem checks do not prove that an Agent loaded or executed a Skill.

Management records remain local in `agent-skill-access.json`. Existing external files are not automatically adopted. If configured Agent directories change, access management fails closed rather than silently moving ownership; the rest of the application can still start.

## Updating

Apple Silicon users on v0.1.10 or later can open Settings > About to download this update, then choose **Restart and update**. Open terminal sessions end during the restart. Your saved shelf, Packs, and settings are retained.

Apple Silicon users on v0.1.9 or earlier, or whose current build cannot open, should install this release manually. Quit Skill Shelf, open the installer, and replace the app in a writable Applications folder. Your saved application data is retained.

Intel users can continue using v0.1.6; new releases support Apple Silicon only.
